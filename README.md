# Our Wedding Planner

두 사람을 위한 개인용 결혼 준비 웹앱. Google 스프레드시트 **결혼 계획표_공유용**의 실제 기록을 그대로 옮겨와,
클릭 몇 번으로 고치고 예산·일정·진행률을 자동으로 계산합니다.

- 결혼식: **2026년 12월 20일(일) 오후 1시** (설정에서 변경) · Timezone: Asia/Seoul
- Next.js 15 (App Router) · TypeScript · Tailwind CSS v4 · Supabase · Framer Motion · Zustand · Lucide

## 정보 구조

최상위 메뉴는 6개뿐이고, 나머지는 각 화면 안의 탭으로 들어갑니다.

| 메뉴 | 경로 | 내부 탭 |
| --- | --- | --- |
| 홈 | `/` | D-Day · 진행률 · 예산 · 지금 해야 할 일 · 다가오는 일정/결제 · 즐겨찾기 · 최근 활동 · 메모 |
| 할 일 · 일정 | `/plan` | 할 일 / 일정 / 당일 진행 |
| 예산 | `/budget` | 요약 / 상세 / 결제 예정 |
| 웨딩 준비 | `/wedding` | 전체 / 식장 / 사진·영상 / 예복 / 헤어·메이크업 / 부케 / 코디네이션 / 음악 |
| 하객 · 초대 | `/guests` | 하객 / 청첩장 모임 / 선물 |
| 신혼여행 | `/honeymoon` | 여행 정보 · 체크리스트 · 여행 일정 |

검색은 상단 바, 설정은 사이드바 아래에 둡니다. 메모함 · 즐겨찾기 · 최근 활동은 홈 위젯과 시트에서 봅니다.
모바일 하단 바는 **홈 / 할 일 / 예산 / 준비 / 하객** 다섯 칸입니다. '일정'은 할 일과 한 화면이 됐으니 탭 하나면 되고,
'메뉴'는 왼쪽 위 ☰ 가 같은 서랍을 열어서 뺐습니다 — 그렇게 비운 두 칸에 매일 여는 웨딩 준비 · 하객을 넣었습니다.
신혼여행 · 설정은 ☰ 서랍에 있습니다. 옛 경로(`/tasks`, `/venue`, `/vendors/*` …)는 새 화면으로 자동 이동합니다.

탭과 필터(`?tab=` `?filter=` `?view=`)는 라우팅 없이 URL에만 남깁니다. `?tab=calendar` 같은 링크로 들어와도 같은 탭이 열리고,
탭 안에서 필터를 눌러도 화면이 바뀌거나 튕기지 않습니다.

### 한눈에 들어오게 만든 것

- **할 일과 일정은 하나**: 추가할 때 "할 일이냐 일정이냐"를 묻지 않습니다. 시간이나 장소를 적으면 일정으로, 안 적으면 할 일로 들어갑니다.
  어느 쪽으로 저장되든 마감일만 있으면 일정 화면에 같이 보이므로, 잘못 골라서 잃어버릴 일이 없습니다. 버튼 글자가 `할 일로 추가` ↔ `일정으로 추가`로 바뀌어 저장 전에 알려줍니다.
- **영역 색**: 준비(분홍) · 일정(파랑) · 예산(초록) · 하객(보라) · 웨딩 준비(주황) · 신혼여행(청록) 6가지를 정해 두고,
  카드 위 3px 띠 · 아이콘 칩 · 메뉴 · 일정 아이콘 · 달력 점이 전부 같은 색을 씁니다. 색은 고정 배정이고 절대 돌려쓰지 않습니다.
  메모함 · 즐겨찾기 · 최근 활동처럼 영역이 없는 카드는 회색 띠라서, 띠 색만 봐도 "이건 어느 쪽 얘기"가 먼저 잡힙니다.
- **색은 눈으로 고르지 않고 검사해서 고정**했습니다. 밝은 · 어두운 테마 각각에서 OKLCH 밝기 구간 · 채도 하한 · 적록색약 분리도(ΔE) · 배경 대비를 재서 통과한 값만 씁니다.
  그래서 **도넛은 큰 3개까지만 색을 주고 나머지는 '그 외' 하나로 접습니다** — 범례와 조각을 아무 짝이나 맞춰 봐야 하는 형태라 모든 쌍이 구분돼야 하는데,
  6종까지 늘리면 주황과 초록이 적록색약에서 사실상 같은 색이 됩니다(ΔE 1.9). 자세한 분해는 옆의 막대 + 이름이 대신합니다.
- **막대는 색으로 크기를 다시 말하지 않습니다**: 카테고리 막대는 길이가 이미 크기를 말하므로 전부 예산 색 하나로 통일했습니다(초과분만 빨강).
- **목록 위 조작 줄을 접었습니다**: 할 일 화면은 진행률 · 추가칸 · 필터 · 검색 · 정렬 · 카테고리가 전부 펼쳐져 있어서
  폰에서 첫 할 일이 화면 밖으로 밀려 있었습니다. 자주 쓰는 필터 칩 한 줄만 남기고 검색 · 정렬 · 카테고리는 버튼 뒤로 접었습니다
  (접혀 있어도 조건이 걸려 있으면 버튼에 숫자가 떠서 "왜 안 보이지"가 생기지 않습니다). 하객 화면도 같습니다.
- **같은 숫자를 두 번 말하지 않습니다**: 탭 바깥 제목 줄과 탭 안 설명이 같은 진행률 · 인원수를 반복하던 것을 한 번만 말하게 했고,
  추가 버튼이 세 개(제목 옆 · 한 줄 추가 · 오른쪽 아래 +)이던 것을 폰에서는 둘로 줄였습니다.
  큰 화면에서는 한 줄 추가 옆의 `자세히` 가 카테고리 · 담당 · 우선순위까지 있는 입력 창을 엽니다.
- **제목이 먼저입니다**: 할 일 줄의 '중요 · 진행 중' 배지를 둘째 줄로 내렸습니다. 같은 줄에 있으면 좁은 화면이나
  큰 글씨(125%)에서 제목이 두어 글자로 잘렸습니다.
- **빈 상자를 만들지 않습니다**: 카드가 행 높이에 맞춰 늘어나지 않게 해 내용 적은 카드가 텅 빈 상자로 보이지 않게 했고,
  예산 요약에서 0원 카테고리 6개는 기본으로 접었습니다.

### 폰에서 한 손으로 쓰도록 챙긴 것

- **한 줄 추가**: 할 일 · 하객 · 예산 항목은 제목만 치고 엔터로 들어갑니다. 지금 보고 있는 필터(오늘 · 카테고리 · 측)를 그대로 물려받습니다.
- **스와이프**: 할 일은 오른쪽으로 밀면 완료 · 왼쪽으로 밀면 마감일, 하객은 오른쪽이 참석 확정 · 왼쪽이 청첩장 전달입니다.
  완료하면 실행 취소 토스트가 5초간 뜹니다. 보이지 않는 동작이라 폰에서는 처음 한 번만 안내가 뜹니다.
- **오늘 카드**: 홈 맨 위에서 지난 마감 · 오늘 마감 · 오늘과 내일 일정을 한 장으로 답합니다. 없으면 "여유 있는 날"이라고 말해줍니다.
- **접기**: 완료한 할 일은 기본으로 접히고, 하객은 관계별로, 예산은 카테고리별로 접었다 펼 수 있습니다.
- **둘이 쓰는 티**: 활동 기록에 누가 고쳤는지 이름이 뜹니다. 설정 › 계정에서 신랑 · 신부를 고르면 할 일을 '내 담당'으로 좁혀 봅니다.
- **모바일 홈 길이**: 3,703px → 1,850px대. 자세한 분석 카드는 큰 화면에서만 펼칩니다(메뉴 › 기록에서 언제든 볼 수 있습니다).
- 하단 탭에서 지금 보고 있는 탭을 다시 누르면 맨 위로 올라갑니다. 입력칸 라벨을 누르면 커서가 들어갑니다.

### 예상 식대

한국 예식장은 **보증 인원**이 있어서 실제로 몇 명이 오든 그만큼은 무조건 냅니다.
그래서 실제 청구 인원은 `max(보증 인원, 오는 사람 수)` 이고, 보증에 못 미치면 빈자리 값을 냅니다.
결혼 예산에서 가장 큰 덩어리인데 손으로 세면 늘 틀리는 계산이라 앱이 대신 합니다 (`src/lib/compute/meal.ts`).

- 인원은 **하객 명단에서 셉니다.** 식장에 따로 적어 둔 '예상 인원' 은 명단이 비었을 때만 씁니다 —
  같은 숫자를 두 군데서 관리하면 반드시 어긋나기 때문입니다.
- 보증에 모자라면 "보증보다 12명 적어요. 안 와도 ₩1,056,000은 그대로 나가요" 처럼 **금액으로** 알려줍니다.
- 식장에 1인 식대를 안 적었으면 계산 대신 적으러 가는 링크를 보여줍니다.
- 하객 화면과 예산 화면에 같은 카드로 나옵니다.

### 하객 세는 법

- **공통 지인**: 신랑 · 신부가 둘 다 아는 사람은 측을 **공통**으로 둡니다.
  양쪽에 한 번씩 세면 총원이 부풀어 식대가 틀어지므로, 겹쳐 세지 않고 제 칸으로 셉니다 (`신랑측 + 신부측 + 공통 = 전체`).
  목록 · 필터 · 요약 숫자가 모두 세 갈래입니다.
- **동반 인원 = 총 인원**: 동반은 *본인을 뺀* 같이 오는 사람 수입니다. 동반 1명이면 총 2명입니다.
  부부를 한 줄로 적을 때(`김철수 & 이영희`) 동반 1명으로 두면 딱 맞습니다.
  헷갈리지 않도록 목록 줄에는 `2명` 배지가, 편집 창에는 `총 2명` 이 함께 보입니다.
- ⚠️ **공통 지인은 SQL 을 한 번 더 실행해야 씁니다.** 이미 설치한 프로젝트라면
  `supabase/migrations/0005_guest_side_both.sql` 한 파일만 SQL Editor 에 붙여넣고 Run 하세요(짧아서 한 화면에 들어옵니다).
  안 하고 '공통'을 고르면 앱이 "SQL 을 한 번 더 실행하세요" 라고 무엇을 해야 하는지 알려줍니다.

### 지우기 · 말로 넣기

- **삭제**: 할 일 · 비용 · 하객 · 메모를 비롯해 모든 항목은 눌러서 연 창 아래의 **삭제** 버튼으로 지웁니다.
  (원래도 있었지만 글자 없는 휴지통 아이콘이라 아무도 못 찾았습니다 — 글자를 붙였습니다.)
  지우면 6초 동안 **실행 취소**가 떠서 잘못 눌러도 되돌릴 수 있고, 무엇을 지웠는지는 최근 활동에 남습니다.
- **말로 넣기**: 할 일 · 하객 한 줄 추가 칸과 메모 창에 마이크 버튼이 있습니다. 말하면 글자로 받아 적어 주고,
  **저장은 직접 눌러야 합니다** — 사람 이름은 곧잘 틀리게 알아들어서 눈으로 보고 고칠 틈이 필요합니다.
- **말로 하객 여러 명**: 하객 화면의 `말로 여러 명 한 번에 담기`. 한 명씩 이름을 말하고 잠깐 쉬면 한 줄씩 쌓입니다.
  쌓인 목록을 고친 뒤 한 번에 저장합니다.
- **한 줄 추가도 같은 말을 알아듣습니다**: 손으로 쳐도 말할 때와 똑같이 읽습니다(`src/lib/voice-guest.ts`, 검사는 `qa/parse.mjs` 20가지).
  - `양가 친구 박준영` → 공통 지인 · 친구
  - `김철수 & 이영희 부부` → 이름 그대로, 동반 1명(총 2명)
  - `신부측 직장 이가족 4명` → 신부측 · 직장 · 총 4명 (이름 속 '가족'을 관계로 오인하지 않습니다)
  - 브라우저가 직접 제공하는 기능이라 서버도 키도 따로 없습니다. **안드로이드 크롬에서 가장 잘 됩니다.**
  - 크롬 계열은 소리를 글자로 바꾸는 과정을 구글 서버에서 합니다. 하객 실명을 다루므로 이 점을 화면에도 적어 두었습니다.
    소리 자체는 앱에 저장하지 않습니다.
  - **아이폰 사파리**는 한 마디가 끝나면 인식을 스스로 닫고 자동 이어듣기를 막습니다. 그래서 한 명 말할 때마다
    마이크를 다시 눌러야 하며, 앱이 기기를 알아보고 그렇게 안내합니다. (담기는 결과는 같습니다)
  - 그래도 안 되면 **키보드의 마이크 버튼**으로 `한 줄로 추가` 칸에 말해도 똑같이 들어갑니다 — 위의 말 알아듣기가 그대로 적용됩니다.
  - 아예 못 쓰는 기기에서는 버튼이 보이지 않습니다.

### 스프레드시트를 열 이유가 없도록 챙긴 것

- **당일 진행표** (`/plan?tab=day`): 원본 '일정' 시트의 시간 · 항목 · 메모 구조를 그대로 이어받아 결혼식 당일 일정을 시간순으로 적고, 사회 · 축사 · 축가 · 부케 · 주례 역할을 한곳에 둡니다. 원본 할 일 메모의 "사회: 강래원오빠 축사: 지언언니"를 옮겨왔습니다.
- **하객 청첩장 원탭**: 하객 행의 봉투 아이콘 한 번으로 청첩장 전달 여부를 바꾸고, 통계 카드에 `전달 / 전체`가 바로 반영됩니다.
- **금액 없는 예산 항목 접기**: 견적도 실제 금액도 없는 항목은 기본으로 접어 두고, 칩 하나로 펼칩니다.
- **날짜 미정 할 일**: 홈 '지금 해야 할 일' 아래에 마감일 없는 할 일 수를 보여주고, 한 번에 '날짜 미정' 필터로 갑니다.
- **홈 안내**: 신랑 · 신부 이름이 비어 있으면, 그리고 (로컬 저장 모드에서) 백업이 오래됐으면 홈 맨 위에 한 줄로 알려줍니다. '나중에'는 7일 뒤 다시 알림입니다.

### 안전망 · 오프라인

- **자동 스냅샷** (로컬 저장 모드): 하루의 첫 수정 직전 상태와, 되돌리기 · 전체 비우기 · 백업 복원처럼 통째로 바꾸기 직전 상태를 브라우저 안에 남깁니다. **설정 › 데이터 관리 › 자동 스냅샷**에서 그 시점으로 되돌릴 수 있습니다.
- **JSON 백업 시점 기억**: 마지막 백업이 언제였는지 데이터 관리에 표시하고, 수정 후 7일(첫 백업 전엔 3일)이 지나면 홈에서 백업을 권합니다.
- **오프라인**: 서비스 워커(`public/sw.js`)가 정적 파일과 마지막으로 본 화면을 캐시합니다. 지하철에서도 앱이 열리고, 로컬 저장 모드면 기록도 그대로 됩니다. 새 버전이 배포되면 '새로고침' 토스트가 뜹니다. (개발 서버에서는 등록하지 않습니다.)

## 원본 데이터 이관

`scripts/build_migration.py` 가 원본 xlsx를 읽어 `src/lib/db/original-data.ts` 를 만듭니다.
앱은 첫 실행 때 이 데이터셋으로 워크스페이스를 채웁니다. 샘플·더미 데이터는 쓰지 않습니다.

```bash
pip install openpyxl
python3 scripts/build_migration.py <원본.xlsx>   # data/original-sheets.json 스냅샷도 함께 생성
```

### 둘이 같이 쓰려면

두 사람이 같은 화면을 보고 수정이 서로 연동되려면 **Supabase 연결이 필요합니다.** 브라우저 저장소는 기기 밖으로 나가지 않기 때문입니다.
설정 순서는 [`docs/SUPABASE.md`](docs/SUPABASE.md) 에 15분짜리 단계로 적어두었습니다. 요약하면:

1. **새** Supabase 프로젝트 생성 (무료, Seoul 리전). 쓰던 프로젝트에 설치하면 `tasks` · `payments` 같은 이름이 겹칩니다
2. SQL Editor 에서 **`supabase/setup.sql`** 전체를 붙여넣고 한 번 Run (세 개 마이그레이션이 순서대로 들어 있음)
3. Vercel 에 배포하고 `NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_ANON_KEY` 등록 후 재배포
4. 한 사람이 가입하면서 시작 데이터를 고르고(**이 기기에서 쓰던 기록 그대로** / 원본 151건 / 빈 상태),
   설정 › 계정에서 **초대 링크**를 상대에게 전달
5. 설정 › 계정 › **연결 점검** 으로 표 설치 · 쓰기 권한 · 실시간까지 한 번에 확인

`0002`는 `weddings.details` 컬럼과 결혼식 날짜 범위 제약(1970~2100)을 추가해 1900-01-01 같은 값을 막습니다.
`0003`은 모든 테이블에 `REPLICA IDENTITY FULL` 을 걸어 **상대가 삭제한 항목도 실시간으로 전달**되게 합니다.
`setup.sql` 맨 앞에는 이름이 겹치는 표가 있으면 아무것도 건드리지 않고 멈추는 안전장치가 있습니다.

로컬 모드로 쓰던 기록은 가입할 때 **그대로 올라갑니다**(`src/lib/db/handoff.ts`). 옮길 때 두 가지를 맞춰 줍니다.
외래키 때문에 예산 카테고리 → 항목 → 결제 순서로 넣고, 로컬 전용 값인 활동 기록의 `user_id` 를 실제 계정으로 바꿉니다.
같은 id 는 덮어쓰므로 중간에 끊겨도 다시 눌러 이어갈 수 있습니다.
다른 프로젝트에 잘못 실행했는지 확인하려면 `supabase/inspect.sql`(읽기 전용), 지우려면 `supabase/uninstall.sql` 을 쓰세요.
연결 상태는 설정 › 계정의 배지와 상단 프로필 옆 초록 점으로 확인할 수 있습니다.

## 성능

모든 앱 화면이 정적 라우트라 메뉴 전환에 서버 왕복이 없습니다. 인증은 middleware가, 워크스페이스 결정은 클라이언트가 한 번만 합니다.

```
메뉴 전환 (클릭 → 콘텐츠 표시)   43 ~ 175ms   추가 네트워크 요청 0건
화면 안 탭 전환                  70 ~ 110ms   (라우팅 없이 history.replaceState 만)
```

화면 진입 모션은 0.22초 fade + 6px slide이며 exit 애니메이션을 쓰지 않아 다음 화면이 기다리지 않습니다.
